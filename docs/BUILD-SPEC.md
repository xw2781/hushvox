# HushVox — build spec (internal; delete or move out before public release)

Goal: open-source (MIT), in-browser, local-only voice noise removal / speech enhancement web tool — an honest alternative to Adobe Podcast Enhance. Audio never leaves the browser, no login, free. Static site (GitHub Pages deployable, no backend).

## Model (decided)
DeepFilterNet3 (code + weights dual-licensed MIT OR Apache-2.0, upstream https://github.com/Rikorose/DeepFilterNet). Use npm package `@lofcz/deepfilternet-web@0.1.0` (WASM SIMD build of libDF, model baked into df_bg.wasm ~34 MB, ~12 MB gzipped; MIT OR Apache-2.0). A copy of the tarball is at /workspace/scratch/lofcz-deepfilternet-web-0.1.0.tgz and unpacked at /workspace/scratch/l/package (read dist/index.js, dist/DeepFilter.d.ts). API: `DeepFilter.create({attenuationLimit, wasmUrl})`, `df.process(frame: Float32Array /*df.frameLength samples @48kHz mono*/) -> Float32Array`, `setAttenuationLimit(db)`, `setPostFilterBeta`, `destroy()`. Model works at 48 kHz mono, has algorithmic latency that you must compensate (measure it; trim start / flush tail with zero padding so output length == input length and is time-aligned).
Record license in README + NOTICE (include upstream MIT/Apache texts + the Rikorose copyright; note npm wrapper by lofcz).
Do NOT ship the CC BY-NC speech clip in git (tests/local-fixtures is gitignored; use it only for local tests). For committed fixtures, use synthetic or CC0/public-domain speech only, with provenance in tests/fixtures/README.

## Stack
Vite + TypeScript, vanilla (no React needed), minimal deps. `npm run dev`, `npm run build` -> dist/. Vite `base` must be configurable (env VITE_BASE) so it works on GitHub Pages project path `/hushvox/` and at root. Load wasm via a URL (copy to public/ or import with ?url), fetch lazily only when the user first processes a file (show "Loading model (12 MB, cached after first time)" with progress). Cache with a Service Worker or at least HTTP caching; keep it simple and correct (if you add a SW, make it safe on updates).

## Functional requirements
1. Drag & drop + file picker for audio (wav, mp3, m4a/aac, ogg, flac, webm; also accept video files and extract audio if the browser can decode it). Decode with Web Audio `decodeAudioData` (main thread) -> resample to 48 kHz via OfflineAudioContext; handle mono/stereo (process each channel separately with its own DeepFilter state, up to 2 channels; downmix >2). Friendly error if decode fails.
2. Processing in a Web Worker (never block UI). Process in chunks (e.g. a few seconds at a time, transferred buffers) so long files (1h+) don't need one giant message; post progress; support Cancel. Avoid holding more copies of the data than necessary (Float32 arrays only). Report speed as "xN realtime".
3. Strength / mix control: process once at full strength, then a live "Strength" slider (0-100%) that blends dry/wet in real time on the main thread during playback and on export (no reprocessing). Optionally also an "advanced" attenuation-limit selector that reprocesses (nice-to-have).
4. A/B comparison: waveform (canvas) of original and enhanced, a single transport (play/pause/seek), and an instant "Original / Enhanced" toggle that switches between sources at the same playhead position without gaps (keep both in sync; use Web Audio with gain nodes or two AudioBufferSourceNodes started together). Keyboard: space = play/pause, A/B keys or Tab-free toggle.
5. Export: WAV (16-bit PCM, original channel count, 48 kHz) and MP3 (lazy-loaded encoder in its own chunk; verify license of the encoder you pick — if LGPL e.g. lamejs, say so in NOTICE and keep it a separate, lazy-loaded, replaceable chunk; MIT/BSD alternative preferred if one works well). Export uses the current strength setting. Filename `<name>-hushvox.wav|mp3`.
6. Mic-free, upload-free: add a visible "Files never leave your device" note and make it TRUE: no analytics, no third-party requests at runtime (fonts must be self-hosted/system fonts; no CDN). Add a strict CSP meta tag (default-src 'self'; allow 'wasm-unsafe-eval', worker-src 'self' blob:, media-src blob:, connect-src 'self'). Verify in the Playwright test that zero external network requests occur.
7. UI: clean, polished, fast, responsive (mobile-first; test at 390x844 and 1440x900), dark + light via prefers-color-scheme, accessible (labels, focus, aria on progress/slider, reduced-motion). Pleasant, restrained visual design (not generic AI-gradient look): a clear hero with the drop zone as the primary element, state flow: idle -> loading model -> processing (progress bar, ETA, speed) -> result (A/B player, strength slider, export buttons, "process another file").
8. Landing/SEO section below the tool (honest copy, no fake claims, no fake testimonials/stats/ratings): what it does, how it works (DeepFilterNet3 running as WebAssembly in your browser), privacy, FAQ (what formats, how long a file, why 48kHz, limits: it's a noise suppressor, not a magic studio-voice generator, may sound slightly processed on heavy noise, music is not preserved, not for already-clean audio), comparison vs cloud tools stated factually (no named-competitor bashing, no claims of beating Adobe), keyboard shortcuts, license/credits. Proper <title>, meta description, canonical placeholder, Open Graph/Twitter tags, JSON-LD (SoftwareApplication, FAQPage matching visible FAQ), semantic headings, robots.txt, sitemap.xml (use a placeholder base URL configured in one place), favicon/OG image (make an SVG logo + a generated PNG OG image 1200x630).
9. Honest quality notes in README (what it is good/bad at).

Write results to tests/RESULTS.md (with machine info: headless Chromium, CPU count) — real measured numbers only.
